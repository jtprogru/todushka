# Code Review: readonly-mode

## Verdict: NEEDS_CHANGES

Реализация в целом соответствует утверждённому пост-pivot плану (Option B): `storage.ErrReadOnly` + `Repository.ReadOnly()` добавлены, bbolt получил `readOnly` поле, `OpenReadOnly` constructor и `checkWritable()` guard на всех 16 write-методах. CLI пробрасывает `--readonly`/`--ro` через cobra, TUI отображает chip `-- READ-ONLY --` и блокирует write-keys. Все базовые проверки (`task test`, `task test-race`, `task build`, `task lint`, `gofmt -l`) проходят без ошибок. Однако обнаружено одно `major` расхождение: `cmd/todushka/main.go` использует ручной pre-scan `hasReadOnlyFlag`, который **не распознаёт стандартную форму `--readonly=true`/`--ro=true`**, в результате чего REQ-4.2 / REQ-5.1 (explicit flag forces RO) нарушается для этой формы — write-операции при таком вызове проходят. Cobra при этом флаг распарсит и пометит `deps.ReadOnly=true`, поэтому видимое поведение `--readonly` и `--readonly=true` расходится (silent bypass). Это блокирует `PASS`.

## Security

| Категория | Оценка |
|-----------|--------|
| Input validation на `OpenReadOnly` | Путь приходит из конфига (`config.DataDir`) — controlled. `os.Stat` + `bolt.Open` корректно обрабатывают неверные пути. ✅ |
| Path traversal | DB path детерминирован — `filepath.Join(dataDir, "db")`. Внешним вводом не управляется. ✅ |
| Permissions | `OpenReadOnly` использует `0o600` mode (тот же, что у write `Open`); поскольку bbolt в RO режиме НЕ создаёт файл (защищено `os.Stat` pre-check), perm — moot, существующие perm файла наследуются ОС. ✅ |
| `hasReadOnlyFlag` scan / bypass | Логика останавливается на первом non-flag arg (любой arg без префикса `-`). Это **корректно** для предотвращения "случайной" интерпретации позиционных аргументов как флагов (например, `todushka complete --readonly` — здесь `complete` не флаг, и `--readonly` после неё не сработает, **но это коррелирует с обычной cobra-семантикой**: persistent flags могут идти и до и после команды; cobra их парсит, а pre-scan — нет). Edge cases: `--` (POSIX end-of-flags) — присутствует префикс `-`, цикл продолжает. **`--readonly=true` НЕ распознаётся** — см. F-1. |
| Error leakage | Сообщение "todushka: database is locked by another todushka process" не утечёт ничего секретного (имя бинарника). Hint про `--readonly` информативен. ✅ |
| Secret exposure | Нет hardcoded токенов/паролей. ✅ |
| Injection / XSS / SQL | N/A для bbolt-based local store. ✅ |
| New endpoints | Нет — это CLI/TUI feature без сетевых endpoints. ✅ |

Основная находка тут — F-1 относится к корректности, а не к security в строгом смысле. Тем не менее **divergence между cobra-parsed `deps.ReadOnly` и open-time `hasReadOnlyFlag`** — это потенциальный source of confusion: пользователь может подумать, что `--readonly=true` защищает базу от модификаций, а на деле — нет.
