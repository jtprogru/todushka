## Design Conformance

### 3.1 Architectural Boundaries

✅ Слои уважены: domain/* не импортирует storage/app/cli/tui; storage не импортирует app/cli/tui; app не импортирует cli/tui; cli/tui импортируют app. Проверено grep'ом по импортам — циклов нет.

✅ TUI и CLI оба используют `app.Service` как единственный mutator, как заложено в design §2.1.

### 3.2 Data Models

✅ Все типы (Task, Project, Heading, Area, Tag, Rule, ChecklistItem, Snapshot) соответствуют design §2.5. JSON-теги `omitempty` на nullable-полях есть. Date с явным MarshalJSON `YYYY-MM-DD`.

✅ bbolt-buckets: `meta`, `tasks`, `projects`, `headings`, `areas`, `tags`, `idx_tag_by_normalized`, `idx_area_by_normalized`. FK-индексы (`idx_tasks_by_status` etc.) НЕ созданы — implementation report явно зафиксировал scope-cut.

### 3.3 API Contracts

✅ Repository interface match design §2.3 + `TagCreate(ctx, tag.Tag) error` добавлен для round-trip импорта (документировано в implementation report как корректировка дизайна).

✅ Cobra subcommands совпадают с REQ-11.x; флаги (`--project`, `--area`, `--tag`, `--start`, `--deadline`, `--someday`) присутствуют.

### 3.4 Error Handling

✅ Доменные ошибки экспортируются (ErrEmptyTitle, ErrDeadlineBeforeStart, ErrAmbiguousProject, ErrSchemaTooNew, ErrDatabaseLocked, etc.).

✅ TUI: `errorMsg` → status bar с auto-fade через `tea.Tick(5s)`. CLI: stderr + non-zero exit code.

⚠️ SIGTERM/SIGINT: Bubble Tea ловит Ctrl+C через `tea.KeyCtrlC` (REQ-12.3 покрыт). Внешний `signal.Notify(SIGTERM)` отсутствует. bbolt устойчив к abrupt termination (double-write headers), так что в практике это безопасно, но не идеально. Минорно.

24 из 25 CP покрыты explicitly (см. traceability table). **CP-24 (synchronous commit durability)** покрывается косвенно через `TestBbolt_TaskRoundTrip`, но без close→reopen — не подтверждает persistence через перезапуск процесса. См. F-2.

### 3.6 Documentation Consistency

Диаграмма из design §2.2 описывает слои; фактический код им соответствует. Имена пакетов в коде совпадают с метками диаграммы. ## Security

Скан изменённых файлов:

- **Input validation:** Cobra-флаги парсятся pflag, JSON-import через `json.Decoder` без `DisallowUnknownFields()` — допускает unknown fields в snapshot, что снимает риск ошибок при добавлении полей в v2 (поведенчески ОК). `--json <path>` помечен `#nosec G304` — user-provided path по дизайну.
- **Authentication / Authorization:** не применимо — однопользовательский локальный CLI.
- **Injection:** SQL не используется (KV-store). JSON парсинг — стандартный stdlib. Quick Entry parser — собственный tokenizer без regex eval.
- **Secrets:** в коде нет hardcoded credentials. БД в plaintext на диске — документировано в README.
- **Data exposure:** export пишет полный snapshot в stdout по умолчанию (REQ-10.1). Это намеренное поведение; пользователь может перенаправить в файл.
- **Error leakage:** ошибки в stderr содержат сообщения вида `"--start: ...: invalid date"` — информативно, без утечек путей/состояния.
- **API chain audit:** нет новых HTTP-эндпоинтов; security scan завершён.

**Security findings:** none.
